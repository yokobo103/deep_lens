# Deep Lens アイコン仕様

2026-09-05 起案。アセット制作に渡すための簡易設計。

## この装置でアイコンが担っていること

Deep Lensは、地球を触ったときに**時代を移動しても同じ場所・同じ生き物を見失わない**ことで成り立っている。
時代を送ると、生きた姿がその場で残り方に変わる（ドリフト）。

だからアイコンは「古代の生き物一覧」と「化石の一覧」の**2つの体系ではない**。
**1つのものが、2つの姿を持つ。** 対応表が仕様の中心。

もう1つの制約は憲章から来る。**凡例を読ませない。**
「まず見る → 気になる → それから読む」の順番なので、凡例を見ないと意味が分からない記号は失格。

## いま壊れていること（作り直す理由）

- 17記録のうち**10件が2つの絵柄に集中**。Spinosaurus と竜脚類が同じ🦕、獣脚類5種が全部同じ🦖
- 17個のうち**8個が活字記号**（✣ ≋ ⌁ ♠ ◇ ≈ ◢ ◒）で、絵文字6個と混在。2つの体系が同居している
- **現代側は4地域すべて同じ🦴**。だがPBDBの記録では、アメリカ（グリーンホーン）はサメ235・二枚貝148・アンモナイト114で、骨はほぼ出ない。骨アイコンは省略ではなく事実と食い違っている

## 3つの層

### 層1 — 地域マーカー（4個）

その地域が**当時どんな世界だったか**。色はアプリ内で既に使っている環境4色を当てるので、形は世界の型だけ表す。

| id | 意味 | 色 |
|---|---|---|
| `world-sea` | 開けた海・内海 | `#378add` |
| `world-delta` | デルタ・沿岸・河口 | `#1d9e75` |
| `world-river` | 川・湖・湿地 | `#97c459` |
| `world-dryland` | 乾いた内陸 | `#ef9f27` |

### 層2 — 生き物（古代側・13個）

### 層3 — 残り方（現代側・6個）

骨・歯・巻いた殻・二枚の殻・葉の圧痕・足跡。「実際に何が残っているか」を示すレイヤーとして
アセットは用意してあるが、**マーカーには使っていない**（下の「対の作り方」を参照）。

## 対の作り方（2026-09-05 修正）

**生き物は、古代でも現代でも自分の姿のまま。変わるのは色だけ。**

最初は「生き物 → 残り方（骨・歯・殻）」に変形させる設計にしていたが、これは間違いだった。
よこぼの指摘: **「アイコンは茶色でね。骨じゃない」**。

スピノサウルスを一般名詞の骨に変えてしまうと、**時代を渡っても同じ動物を見ている**という、
ドリフトが見せようとしている唯一のことが消える。
カラフルなスピノサウルスが、茶色のスピノサウルスになる。それだけでいい。

地域マーカーも同じで、当時の世界（デルタ・川・海）が、現代では茶色のその形になる。

## 作りの規格

短くする。細かい規則を積むほど質が落ちるので、締めるのは上位カテゴリだけにする。

- **単色シルエット、塗りのみ。** 線画にしない。`fill="currentColor"` 固定で、色はCSS側で当てる
- **`viewBox="0 0 24 24"`。** 表示は22〜30px
- **図形が枠の80%以上を占めること。** 余白の割合ではなく、占有率で見る（小さく出る事故が起きる）
- **最も細い部分が0.9単位（≒1px）を下回らない。** 22pxに縮めた瞬間に消える
- **生き物はすべて左向き。** 例外を作らない
- グラデーション・影・テキスト・複数色は使わない。`<path>` だけ
- 1ファイル1アイコン。`icons/world/sea.svg` `icons/life/theropod.svg` `icons/trace/bone.svg`

## 合否の見かた

**凡例を隠して、全部22pxに縮めて、実際の地球の背景（濃い青緑と砂色）の上に並べる。**
そのとき、どれがどれか言えるかどうかだけで判定する。文章の説明を読ませない。

判定は1案ずつの合否ではなく、**並べて選ぶ**。却下したものは理由を添えて残し、次の生成に効かせる。

なので**各アイコンを1案に絞らず、少なくとも2つの方向で全セットを作る**こと。
（例：厚みのある塊のシルエット／細身で特徴を強調したシルエット）

## 移行のしかた

`src/components/lifeIcons.ts` の1つのマップを差し替えれば移行できる。
絵文字は残さず全部入れ替える。混在が今回の壊れ方の原因なので。

## 色の規則（2026-09-05 決定）

**古代はカラフル、現代は茶色一色。** よこぼの決定。

生きていた世界はにぎやかで、残された痕跡は静か、というビジョンの区別を、
説明ではなく色そのもので出す。ドリフトで時代を渡ると、色が抜けていく。

同じ絵を2つの姿で書き出している（`tools/build-icons.py`）。

- `src/assets/icons/color/` — 描かれたまま。生きている地球用
- `src/assets/icons/trace/` — 輝度を茶色のランプに写したもの。痕跡用

**最初は単色シルエット（アルファのみ）で作ろうとして失敗した。** この絵は貝の筋や
アンモナイトの渦など**内側の線で形を作っている**ので、シルエットにすると全部同じ塊になる。
輝度を茶色に写せば内側の線が残り、しかも現代側は静かな茶色の一族に収まる。

### いまの穴

**歯のアイコンが無い。** シートの該当マスがシダの葉になっていた（`trace-frond`）。
サメとエイは暫定で骨を借りている。グリーンホーンはサメ235件の産地なので、
**次にシートを描き直すときの最優先はこれ**。地域の既定はアンモナイトの殻に逃がしてある（114件）。

## 差し替えかた（2026-09-05 実装）

絵とデータは切り離してある。データが持っているのは**カテゴリ名**（`theropod`、`delta`）だけで、
ファイル名は一度も出てこない。あいだに `src/components/iconRegistry.ts` の対応表が1枚あるだけ。

### 全部描き直したとき

新しいシート1枚を渡して、これを流すだけ。

```bash
python tools/build-icons.py <sheet.png>
```

格子はアルファから自動で見つけるので、マスの位置が多少ずれても切れる。
読む順番は `ICON_ORDER`。コードは1行も触らない。

### 形式を変えたいとき（PNG → SVG など）

`color/` と `trace/` に `.svg` を置けばよい。globは `*.{png,svg,webp}` を見ている。
その場合は茶色版も自分で用意する（ツールを通さないので）。

### どのカテゴリにどの絵を当てるかを変えたいとき

`iconRegistry.ts` の2つの表だけ。

- `ANCIENT_ICON` — カテゴリ → その生き物・その世界の絵
- `REGION_ICON` — 地域 → 現代側の地域マーカーに使う世界の絵

**「生き物 → 残り方」の対応表は無い。** 生き物は自分の姿のまま、色だけが変わるので。

### 増やしたいとき

新しいシートに絵を足して焼き直し、`ANCIENT_ICON` に1行足す。
対応表に無いカテゴリは既定の絵に落ちるので、**表を書き忘れても画面は壊れない**。

### 種ごとの現代マーカー

現代側には、その生き物が**いま実際に掘り出されている場所**にマーカーが立つ。
位置と地点数は `npm run data:taxa`（`tools/build-taxon-traces.mjs`）がPBDBから焼く。
分類群は `ancientLife.ts` から読むので、生き物を足せば次回の焼き直しで自動的に増える。
